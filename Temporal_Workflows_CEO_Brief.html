Executive Summary

The Cyber Towers Vehicle Access Dashboard currently monitors real-time gate entries and exits. However, several critical business processes — such as overstay alerts, unauthorized vehicle approvals, and nightly reports — run on a fragile infrastructure that loses all memory when the server restarts, has no retry mechanism if something fails, and cannot escalate issues automatically. This document proposes the introduction of Temporal Workflows — a modern automation platform — to make these processes reliable, self-healing, and intelligent.

What is Temporal?

Temporal is a workflow automation platform that allows us to run critical business processes as durable, self-healing programs. Unlike traditional systems where a process is lost if the server restarts or an email fails to send, Temporal remembers exactly where it left off — even after a crash, a power cut, or a server restart.

Think of it like this: today, if the server is restarted at 11:55 PM, the nightly summary email — scheduled for 11:59 PM — is simply never sent. With Temporal, it will run the moment the server comes back online, even if that is 2 AM.

Similarly, today a vehicle that has been inside for 27 hours triggers an alert email — but if the server restarts before the next check, it will trigger the exact same alert again. Temporal prevents this by storing the alert history durably on disk, not in temporary memory.

Current System — Key Problems

Before presenting the workflows, here are the three critical problems the current system has that Temporal is designed to solve:

# Problem What Happens Today Business Impact
P1 Overstay alerts are sent twice after a server restart The list of vehicles already warned is stored in temporary memory. Any restart wipes it. Security team receives duplicate alert emails. Creates confusion and loss of trust in the system.
P2 Nightly report is missed if server is down at 11:59 PM The report runs on a simple timer. If the server is not online at exactly 11:59 PM, the report is permanently skipped. Management does not receive the daily vehicle summary. No audit trail for that day.
P3 Unauthorized vehicle approvals exist only in one browser When security approves an unauthorized vehicle, that record is stored only in the browser's local storage on that one computer. If security opens a different computer, or clears the browser, all approval records disappear. No audit trail. No notifications sent.
P4 No automated gate health monitoring If a physical gate scanner stops working at midnight, nobody knows until a vehicle fails to scan the next morning. Security gap. A broken gate could go undetected for hours.

Detailed Workflow Descriptions

Workflow 1
Vehicle Session Lifecycle
The foundation — one running process for every vehicle currently on the premises
PriorityMedium
When It StartsEvery gate entry scan
When It EndsVehicle exits or 72 hours pass
TypeOne per vehicle

What Is This Workflow?

The moment a vehicle scans at any gate and enters the premises, this workflow starts — one dedicated running process for that specific vehicle. It holds the complete live record of that vehicle's visit: which gate it entered, what time, what type of vehicle, whether it has a parking slot, and how long it has been inside. This process remains active until the vehicle scans at the exit gate and leaves.

Why Is This Needed?

❌ Today's Problem The system currently has no live awareness of which vehicles are inside at any given moment. Every time someone opens the dashboard to check occupancy, it runs a complex database calculation from scratch. There is no "live" tracking per vehicle — only a historical report generated on demand. ✅ With This Workflow Each vehicle has a live, running process that knows its exact status. The dashboard can query it directly: "Is Vehicle X inside? For how long?" This is instant — no database calculation needed. It also becomes the foundation that all other workflows build on.

How Does It Work — Step by Step

  • 1
    Vehicle scans at entry gate. The workflow starts immediately, recording the vehicle's details — card ID, gate number, time, vehicle type.
  • 2
    Checks parking slot. The workflow checks if this vehicle has an assigned parking space. If not, it automatically starts the Parking Slot Management workflow (Workflow 7) in the background.
  • 3
    Starts overstay monitoring. The 24-hour overstay timer is started for this vehicle (Workflow 2 runs alongside this one).
  • 4
    Waits for the vehicle to exit. The workflow simply waits — it could be 20 minutes, 8 hours, or 2 days. Temporal keeps it alive no matter how long.
  • 5
    Exit scan received. When the vehicle exits, this workflow receives the signal, closes the session, stops the overstay timer, and records the session duration.
  • 6
    Safety cutoff. If 72 hours pass with no exit scan, the workflow sends a final critical alert and closes the session automatically.
Business Benefits:
Real-time vehicle status without DB query
Foundation for all other automation
Automatic session duration tracking
72-hour safety cutoff
Workflow 2
Overstay Alert & Escalation
Per-vehicle 24-hour timer — survives server restarts — escalates if ignored
PriorityHIGH — Fixes Existing Bug
When It StartsEvery gate entry scan
When It EndsVehicle exits (cancelled) or 72h
TypeOne per vehicle

What Is This Workflow?

The moment a vehicle enters, a 24-hour countdown timer starts for it. If the vehicle exits normally before 24 hours, the timer is cancelled automatically and nothing happens. But if the vehicle is still inside after 24 hours — the workflow sends an alert email. If still no exit after another 12 hours, it sends an escalation. It continues escalating every 12 hours until the vehicle leaves or the team takes action.

Why Is This Needed?

❌ Today's Problem (Problem P1) Today, a single cron job (a scheduled task) runs every 30 minutes and checks the entire database for vehicles over 24 hours. The list of vehicles already warned is stored in temporary memory. Every time the server restarts, this list is wiped. Result: a vehicle that was warned at 2 AM will be warned again at 2:01 AM when the server restarts — duplicate emails sent to the admin. ✅ With This Workflow Each vehicle has its own independent 24-hour timer stored on disk. A server restart does not affect it. The timer resumes exactly where it left off. The record of which vehicles were already alerted is stored durably — no more duplicate emails. And the system now escalates automatically — something the current version cannot do at all.

How Does It Work — Step by Step

  • 1
    Vehicle enters the gate. A 24-hour countdown begins, stored permanently on disk.
  • 2
    Vehicle exits normally (before 24 hours). The countdown is cancelled. Nothing else happens.
  • 3
    24 hours pass — vehicle still inside. An alert email is sent to the admin with vehicle details, entry time, and company information.
  • 4
    Every 12 hours after that — the system checks again. If the vehicle is still inside, an escalation email is sent with increasing urgency to a wider group of recipients.
  • 5
    At 72 hours — a final critical alert is sent to the full management team. The workflow closes automatically.

Workflow 3
Unauthorized Vehicle Approval
Server-side approval with notification, timeout, and full audit trail
PriorityHIGH — Fixes Existing Bug
When It StartsUnknown vehicle scans at entry
When It EndsApproved, denied, or 2 hours pass
TypeOne per unauthorized entry

What Is This Workflow?

When a vehicle with an unregistered RFID card scans at the gate, the dashboard currently shows an "Unauthorized" badge. The security officer can click an "Allow" button and add a remark. This workflow transforms that manual step into an automated, server-side process: it immediately notifies the security officer, waits for their decision, and escalates if no response comes within 30 minutes.

Why Is This Needed?

❌ Today's Problem (Problem P3) The approval is saved only in the local storage of the browser on that specific computer. If the security officer uses a different computer, or the browser cache is cleared, all approval records are permanently lost. There is no notification sent to the officer — they only see it if they are already looking at the dashboard. There is no audit trail. There is no timeout. ✅ With This Workflow The approval is stored on the server, visible from any device. The security officer receives an immediate notification (email or SMS). If no response in 30 minutes, the system escalates automatically to the facility manager. Every approval or denial is permanently recorded with a timestamp and the name of the officer who made the decision.

How Does It Work — Step by Step

  • 1
    Unknown vehicle scans at gate. The dashboard shows the entry. The workflow starts immediately.
  • 2
    Notification sent to security officer. An email or alert is sent saying: "Unknown vehicle at Gate 1 — please review and approve or deny."
  • 3
    The workflow waits for a decision. The security officer can approve (providing vehicle number and reason) or deny from any device connected to the dashboard.
  • 4
    If approved: The vehicle is recorded as "Allowed" with the officer's name, vehicle number, reason, and timestamp — permanently stored on the server. All dashboard users see the updated status.
  • 5
    If no response in 30 minutes: A reminder is sent to the officer and an escalation alert is sent to the facility manager.
  • 6
    If no response in 2 hours: The case is escalated to senior management and the workflow closes with status "No Response — Unresolved."
Business Benefits:
Full audit trail of every unauthorized entry
Automatic notification to security
Visible from any device
Automatic escalation if ignored
Compliance-ready records
Workflow 4
Daily Summary Report
Nightly email guaranteed to be delivered — even if server was down at midnight
PriorityHIGH — Easiest to Build
Schedule11:59 PM every night
Duration~5 minutes to complete
TypeScheduled

What Is This Workflow?

Every night at 11:59 PM, this workflow automatically fetches the day's complete vehicle access summary — total entries, exits, vehicles still inside, overstay count, and unauthorized entry count — and sends a formatted summary email to the management team.

Why Is This Needed?

❌ Today's Problem (Problem P2) The current daily email is sent by a simple timer that fires at exactly 11:59 PM. If the server is restarted, being updated, or facing any downtime at that moment, the timer fires into nothing. The email is permanently missed for that day with no record or catch-up. Additionally, if the email service fails (e.g., wrong password, network issue), there is no retry. The email is simply lost. ✅ With This Workflow Temporal tracks whether the nightly report ran. If the server was down at 11:59 PM and came back at 1 AM, the report runs immediately at 1 AM for the previous day. If the email service fails, Temporal retries automatically up to 5 times with increasing wait intervals. The daily report will always be delivered.

Every Friday evening — week-in-review with trends, peak hours, and insights
PriorityMedium

What Is This Workflow?

Every Friday evening, this workflow generates a comprehensive week-in-review report for facility management. Unlike the daily report which only shows totals, this report includes trends, busiest hours of the week, overstay incidents with company names, Gate 1 vs Gate 2 utilization split, and a comparison to the previous week. This is entirely new functionality that does not exist in the current system.

Why Is This Needed?

Currently, the dashboard shows real-time data and allows viewing daily/weekly bar charts — but there is no automated weekly summary sent to management. Facility managers must log into the dashboard to see trends. This workflow delivers that analysis directly to their inbox every Friday without any action required.

Workflow 6
Gate Health Monitor
Runs 24/7 — alerts within minutes if any gate scanner goes offline
PriorityMedium — New Capability
RunsContinuously, 24/7
Checks Every5 minutes (business hours)
TypeContinuous monitor

What Is This Workflow?

This is a single, continuously running process that monitors both physical gate scanners (Gate 1 and Gate 2) around the clock. Every 5 minutes during business hours, it checks whether each gate has recorded any vehicle scans in the past 30 minutes. If a gate has been completely silent during business hours, that means the RFID scanner has likely malfunctioned — and an immediate alert is sent to the facility manager.

Why Is This Needed?

❌ Today's Problem (Problem P4) There is currently no automated monitoring of the physical gate scanners. If Gate 1's RFID reader stops working at 10 PM, nobody finds out until a vehicle tries to scan the next morning and it fails. In a high-security commercial complex like Cyber Towers, an undetected gate failure is a serious vulnerability. ✅ With This Workflow The moment a gate scanner stops sending data during working hours, the facility manager receives an alert email within 5 minutes. If both gates are simultaneously offline, the alert is immediately critical and is sent to the full management team. When the gate comes back online, a confirmation email is automatically sent.

Workflow 7
Parking Slot Management
Auto-notifies facility manager when a vehicle enters without an assigned slot
PriorityLower Priority
When It StartsVehicle enters with no slot
When It EndsSlot assigned or 2 hours
TypePer vehicle (conditional)

What Is This Workflow?

When a registered vehicle enters Cyber Towers but does not have an assigned parking slot in the system, this workflow automatically notifies the facility manager so they can assign a slot before the vehicle parks in an unauthorised area. The workflow waits for up to 2 hours for the facility manager to assign a slot. If no slot is assigned, the vehicle is directed to overflow parking.

Why Is This Needed?

Currently, if a vehicle enters without an assigned parking slot, nothing happens automatically. The facility manager is only aware of the missing slot if they happen to be looking at the configuration page. This workflow proactively alerts them the moment the vehicle enters, so the situation is handled in real-time.

How Does It Work — Step by Step

  • 1
    Vehicle enters with no parking slot. This workflow is automatically triggered by Workflow 1 (Vehicle Session Lifecycle).
  • 2
    Checks company parking capacity. Looks up how many total slots the company has and how many are currently in use.
  • 3
    If slots are available — sends a notification to the facility manager: "Vehicle X from Company Y has entered without a slot assignment. Please assign."
  • 4
    Facility manager assigns a slot via the configuration page. The dashboard immediately reflects the update for all users. Workflow ends successfully.
  • 5
    If no slots available — the vehicle is directed to overflow parking and the company admin is notified that their parking quota is full.
Business Benefits:
No unauthorized parking
Proactive facility management
Real-time slot assignment visible to all
Workflow 8
Vehicle Registry Sync
Background refresh every 55 seconds — keeps live scans fast and reliable
PriorityLowest Priority
ScheduleEvery 55 seconds
Duration~10 seconds each run
TypeScheduled background

What Is This Workflow?

Every 55 seconds, this workflow quietly fetches the latest vehicle registry from the database and refreshes the system's internal cache. This ensures that whenever a real-time scan arrives at the gate, the system already has fresh vehicle information ready — without needing to make a database call at that exact moment.

Why Is This Needed?

Today, vehicle registry data is fetched from the database at the same moment a gate scan arrives. If the database happens to be slow (even for a few seconds), the real-time dashboard display is delayed. By moving the registry refresh to a background process, the live scan path is always instant — it just reads from a pre-prepared cache.

As an additional benefit, this workflow will allow the Health Check screen in the dashboard to show useful information: how many vehicles are registered, how many are 2-wheelers vs 4-wheelers, and when the registry was last refreshed.

Business Benefits:
Faster real-time scan display
Registry refresh never blocks live data
Health check shows cache status
